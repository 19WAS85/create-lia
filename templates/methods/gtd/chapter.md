## Organization Method: GTD

This workspace organizes content with Getting Things Done: capture everything, clarify each item, and keep the lists trustworthy.

- `inbox/` — everything captured, before clarification.
- `projects/` — outcomes that need more than one action, one document per project: `projects/<name>.md`.
- `reference/` — material kept for consultation: `reference/<topic>.md`.
- `next-actions.md` — the next concrete physical action for each open commitment, verb first.
- `waiting-for.md` — commitments blocked on someone or something else, with what, who, and since when.
- `someday-maybe.md` — ideas parked without commitment.

### The Flow

1. **Capture** everything into `inbox/`.
2. **Clarify** each item: what is the next physical action? If there is none, drop it, park it in `someday-maybe.md`, or define the project it belongs to.
3. **Organize** the clarified item into the correct list. A clarified item leaves the inbox.
4. **Review** weekly, as a ritual: review the lists, update project definitions, and empty the inbox.

### Task Tracking

The lists above are the task system; no `TASKS.md` is generated.

- Register only concrete pending actions. Reference information belongs in `reference/`, not in the lists.
- Before adding an item, look for duplicates and update the existing entry when appropriate.
- Write next actions verb first, as a single concrete physical action.
- On completion or cancellation, remove the item from the active list and record the result in the project document it belonged to, when that document exists.
